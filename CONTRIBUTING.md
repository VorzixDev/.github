# Contributing to VorzixDev Projects

Thank you for your interest in contributing to VorzixDev.

## 1. Before Contributing

Before starting work:

1. Confirm that the repository accepts external contributions.
2. Review the repository README, licence, security policy, and issue tracker.
3. Discuss substantial changes before implementing them.
4. Do not begin confidential or commercial project work without the required written project terms and access approval.

An unsolicited contribution may be reviewed, modified, declined, or closed. Submission or acceptance of a contribution does not automatically create employment, compensation, revenue-share, ownership, or continuing-maintenance rights.

## 2. Intellectual Property and Commercial Contributions

VorzixDev does not accept substantial unsolicited code, assets, audio, models, artwork, animation, documentation, or other copyrightable production work for commercial products unless separate written contribution terms have been accepted.

Opening an issue, submitting an idea, reporting a bug, or discussing a possible improvement does not transfer ownership of the submitter's original work to VorzixDev.

A contributor's copyright and VorzixDev's permission to use, modify, distribute, sublicense, sell, or include a contribution in a commercial product are separate matters and must not be assumed.

Before submitting a substantial contribution, contact VorzixDev to determine whether one or more of the following are required:

- A Project-Specific Agreement
- A Contributor Licence Agreement
- A copyright assignment
- An exclusive or non-exclusive commercial licence
- Repository-specific licence terms
- Other written authorization

Do not submit commercial production work unless the applicable ownership, modification, distribution, sublicensing, customer-use, withdrawal, attribution, and source-file terms have been confirmed in writing.

Unless separate written terms state otherwise:

- VorzixDev does not claim ownership merely because material was discussed or submitted.
- VorzixDev is not required to use, publish, distribute, purchase, or accept a submission.
- The contributor must not represent that VorzixDev has accepted a contribution before a recorded acceptance decision.
- A merged pull request confirms repository acceptance of that change but does not by itself transfer copyright or create commercial rights beyond the applicable repository licence and separately accepted terms.
- A contributor must not withdraw previously granted rights when a valid written agreement makes those rights irrevocable, except where the applicable agreement or law allows it.

VorzixDev may decline substantial external contributions until appropriate written intellectual-property terms are available.

## 3. Types of Contributions

Depending on the repository, contributions may include:

- Code and scripts
- Documentation
- Tests and bug reports
- UI/UX proposals
- 2D or 3D assets
- Animation, VFX, or audio
- Build and workflow improvements
- Security fixes submitted through the approved private process

Repository-specific rules take priority over this default guide.

## 4. Originality, Licensing, and Provenance

Contributors must:

- Submit only work they created or are authorized to use.
- Identify third-party code, assets, fonts, audio, models, textures, plugins, libraries, datasets, and templates.
- Preserve required notices and attribution.
- Disclose licence conditions that may affect commercial use, distribution, modification, sublicensing, or redistribution.
- Disclose material AI assistance when it affects provenance, licensing, security, accuracy, or review.
- Never copy assets or code from games, applications, repositories, media, or marketplaces without permission.
- Keep source links, creator names, licence names, download dates, and required attribution for approved external materials.

VorzixDev may request original source files, project files, dependency information, licences, creation evidence, or a written statement confirming authorship and authorization.

## 5. Development Workflow

Unless a repository says otherwise:

1. Create or reference an approved issue.
2. Work in a separate branch.
3. Keep each pull request focused on one purpose.
4. Use clear commit messages.
5. Add or update tests and documentation where appropriate.
6. Complete the pull-request checklist.
7. Address review comments before requesting final approval.

Do not commit secrets, credentials, tokens, private customer data, payment data, confidential agreements, or unreleased commercial assets to a public repository.

## 6. Code Quality

Code contributions should:

- Be readable, modular, and appropriately documented.
- Validate untrusted input.
- Avoid unnecessary loops, connections, memory leaks, and duplicated logic.
- Prefer configuration over hard-coded project values where appropriate.
- Include error handling and safe defaults.
- Avoid hidden network requests, telemetry, external loaders, backdoors, credential collection, or obfuscated logic.
- Respect client-server boundaries and repository security requirements.

For Luau and Roblox work, server-authoritative validation is expected for security-sensitive actions. Repository-specific architecture and naming rules apply.

## 7. Asset and Media Quality

Non-code deliverables should include, where applicable:

- Editable source files
- Exported production files
- Clear naming and folder structure
- Scale, pivot, hierarchy, and performance information
- Licence and source records
- Technical requirements for integration
- Preview files and reasonable revisions

## 8. Tests and Evidence

A contribution may require:

- Reproduction steps
- Expected and actual results
- Device, platform, engine, and version information
- Screenshots or video
- Logs and error output with sensitive information removed
- Test cases and retest results

Only work recorded as accepted through the applicable review process is treated as an accepted project contribution.

## 9. Review and Acceptance

VorzixDev may mark a submission as:

- Accepted
- Accepted with follow-up work
- Pending revision
- Declined
- Out of scope

Approval of a pull request confirms repository acceptance of that change. It does not by itself modify a contributor's compensation, revenue-share, copyright ownership, commercial-use permission, sublicensing rights, attribution terms, or maintenance obligations.

## 10. Security Reports

Do not open a public issue for a vulnerability, leaked secret, exploit, or access-control problem. Follow [SECURITY.md](SECURITY.md).

## 11. Questions

For contribution and intellectual-property questions, contact **vorzixdev.official@gmail.com** before submitting substantial work.
