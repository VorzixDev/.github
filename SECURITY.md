# VorzixDev Security Policy and Responsible Disclosure

## Reporting a Vulnerability

Do not report a vulnerability through a public issue, discussion, pull request, social post, or public Discord channel.

Use GitHub Private Vulnerability Reporting when enabled for the affected repository, or email **vorzixdev.official@gmail.com** with the subject `Security Report - [Product or Repository Name]`.

## Information to Include

- Affected product, repository, component, and version
- Description and reproduction steps
- Expected and actual behavior
- Potential impact
- Sanitized logs, screenshots, or video
- Suggested mitigation, if available
- Whether the issue was disclosed elsewhere

Do not send passwords, session cookies, payment credentials, government identification, full customer records, or unrelated personal data.

## Severity Guidance

- **Critical:** Unauthorized privileged access, credential exposure, remote code execution, or severe widespread impact.
- **High:** Significant access-control bypass, sensitive-data exposure, or reliable exploitation with major impact.
- **Medium:** Limited security impact requiring specific conditions or user interaction.
- **Low:** Minor hardening issues or low-impact security weaknesses.

Final severity is determined after investigation.

## Responsible Testing

Do not access, modify, or delete data that does not belong to the reporter; disrupt services; use social engineering, malware, denial of service, credential theft, or destructive testing; or expand testing beyond the minimum needed to demonstrate the issue.

## Supported Versions

Supported versions are defined separately in each product's documentation or release notes. Modified customer copies, unsupported forks, unreleased builds, and end-of-support versions may receive limited or no security maintenance unless separately agreed.

## Response Process

VorzixDev may acknowledge the report, request clarification, reproduce and assess the issue, develop and test a fix, coordinate release and disclosure, and publish an advisory where appropriate. No fixed response or resolution time is guaranteed by this public policy.

## Recognition and Compensation

This policy does not create a bug-bounty program, payment obligation, revenue-share right, employment relationship, or guarantee of recognition.
